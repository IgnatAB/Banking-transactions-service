I am writing an example of using the Kafka message broker for fintech

Цель:  
Создать мини-экосистему микросервисов, которая имитирует работу банковской системы с использованием
Kafka для обмена сообщениями.
Приложение показывает:  
•работу кластера Kafka Producer / Consumer   
•Consumer Groups и балансировку нагрузки, подключен Kafka ui для наглядности  
•обработку событий с последующими шагами  
•устойчивость к сбоям (ретраи, dead-letter-topic)  
•многопоточность при генерации сообщений  
•обогащение и сбор логов в файлы для последующего просмотра и анализа
(реализацию работы с логами через ELK решил вынести в отдельное приложение для сокращения размеров
образа и сохранения цели приложения)  
•подключение метрик и дашборда   
________________________________________
## Архитектура
1. Transaction Generator (Producer-сервис)  
- Генерирует клиентов, которые выполняют транзакции  
- Генерирует транзакции со статусом Success и Failed для имитации ошибок:  
  • Пополнение счета  
  • Перевод денег  
  • Оплата покупки   
- Отправляет события в Kafka, в топик transactions  
________________________________________
2. Transaction Processor (Consumer-сервис)  
- Подписан на топик генератора (transactions).  
-	Проверяет:  
  •	статус транзакции,  
  •	достаточно ли средств,  
  •	корректность данных счетов.  
- Если всё хорошо, записывает результат в БД, и отправляет сообщение в approved-transactions.  
- Если транзакция отклонена, отправляет сообщение в топик rejected-transactions.  
- Если ошибка, отправляет сообщение в DLQ топик.  
________________________________________
3. Notification Service (Consumer-сервис)    
• Подписан на оба топика: approved-transactions и rejected-transactions.   
• Читает сообщения из этих топиков и симулирует отправку сообщений (реализовано как запись логов) о результате транзакции клиентам.  
• Если есть ошибка при обработке сообщения, отправляет его в DLQ топик.
________________________________________
4. Dead Letter Queue (DLQ)  
•	Если consumer не может обработать сообщение , например, ошибка сериализации или ошибка соединения,
оно попадает в отдельный топик transactions-dlq.   
•	Отдельный consumer для анализа "плохих сообщений".   
•   Все сообщения записываем в БД  
•   С помощью контроллера можем посмотреть все сообщения, сделать ретрай выбранного (по id) в топик transactions для 
обработки заново и удалить из таблицы обработанное сообщение.
________________________________________
5. Модуль Common (вспомогательный)  
•	Содержит общие пакеты для работы сервисов: DTO, KafkaConfig для Producer и Consumer.  
________________________________________

## Как запустить
Перед первым запуском сгенерируйте новый KAFKA_KRAFT_CLUSTER_ID командой:  
docker run --rm bitnami/kafka:3.7 kafka-storage.sh random-uuid   
Вы получите новый 22-значный ID кластера.  
Затем замените значение в docker-compose.yml для каждого из 3х брокеров:  
- KAFKA_KRAFT_CLUSTER_ID=<новый_id>  
После этого выполните  
  docker-compose down -v  
  docker-compose up -d  

Далее по порядку запускаем сервисы  
1. Transaction Generator  
2. Transaction Processor  
3. Notification Service  
4. Dead Letter
