I am writing an example of using the Kafka message broker for fintech

Цель
Создать мини-экосистему микросервисов, которая имитирует работу банковской системы с использованием Kafka для обмена сообщениями.
Приложение показывает:  
•работу кластера Kafka Producer / Consumer   
•Consumer Groups и балансировку нагрузки, подключен Kafka ui для наглядности  
•обработку событий с последующими шагами (workflow)  
•надежность и fault tolerance (ретраи, dead-letter-topic)  
•многопоточность при генерации сообщений  
•сбор и агрегацию логов  
•подключение метрик и дашборда   
________________________________________
## Архитектура
1. Transaction Generator (Producer-сервис)  
• Генерирует клиентов, которые выполняют транзакции  
• Генерирует транзакции со статусом Success и Failed для имитации ошибок:  
 - Пополнение счета  
 - Перевод денег  
 - Оплата покупки   
• Отправляет события в Kafka, в топик transactions  
________________________________________
2. Transaction Processor (Consumer-сервис)  
• Подписан на топик генератора (transactions).  
•	Проверяет:  
 -	статус транзакции,  
 -	достаточно ли средств,  
 -	корректность данных счетов.  
• Если всё хорошо, записывает результат в БД, и отправляет сообщение в approved-transactions.  
• Если транзакция отклонена, отправляет сообщение в топик rejected-transactions.  
• Если ошибка, отправляет сообщение в DLQ топик.  
________________________________________
3. Notification Service (Consumer-сервис)    
• Подписан на оба топика: approved-transactions и rejected-transactions.   
• Читает сообщения из этих топиков и симулирует отправку сообщений (реализовано как запись логов) о результате транзакции клиентам.  
• Если есть ошибка при обработке сообщения, отправляет его в DLQ топик.
________________________________________
4. Dead Letter Queue (DLQ Service)  
•	Если consumer не может обработать сообщение, например, ошибка сериализации или ошибка соединения, оно попадает в отдельный топик transactions-dlq.  
•	Отдельный consumer для анализа "плохих сообщений".
• запись в БД сообщений
• повторные попытки отправить сообщение в топик transactions для повторной обработки  
• несколькок для  ЭП для просмотра и удаления сообщений из БД.
________________________________________
5. Модуль Common (вспомогательный)
•	Содержит общие пакеты для работы сервисов: DTO, KafkaConfig для Producer и Consumer.  
________________________________________

•	Docker (для Kafka и БД)
